## 本周核心认知清单

- [x] 内存墙的物理根源：GPU 算力每代增长 2-3 倍，HBM 带宽仅增长 1.5-2.4 倍
- [x] Roofline 模型：低算术强度的操作被内存带宽"压死"，GPU 算力再高也没用
- [x] AI 的大量辅助操作（LayerNorm、Softmax、KV Cache）都是内存受限，拖累整体 MFU
- [x] 内存金字塔：SRAM（最快最贵最小）→ HBM → DDR → SSD → 网络存储（最慢最便宜最大）
- [x] SRAM 成本是 HBM 的 50-100 倍——Cerebras 的 44GB SRAM 方案极贵
- [x] 数据搬运消耗的能量是计算本身的 10-100 倍
- [x] HBM 占 GPU 物料成本的 40-60%——SK Hynix 拿走了 GPU 产业链近一半的成本
- [x] HBM 供应链双寡头：SK Hynix（53%）+ Samsung（38%）
- [x] CoWoS 先进封装是 GPU 出货的最紧瓶颈——不是 GPU 芯片不够，是封装不够
- [x] KV Cache 是推理场景的内存墙核心——上下文越长，内存压力越大
- [x] CXL 不能替代 HBM（带宽差 10 倍），但能作为 HBM 的补充（KV Cache 溢出、内存池化）
- [x] 打破内存墙三条路线：搬近（HBM 堆叠）、搬到（存内计算 PIM）、少搬（量化/稀疏化）
- [x] 供应链风险管理的三层防御：多源采购 → 战略锁定 → 架构替代
- [x] NVIDIA 已经在用三星和 Micron 的 HBM——多源采购是"正在做但还不够"的事
- [x] CXL 2.0 的成本效益计算：40% 利用率提升 + 30% 成本增加 = 实际省钱，但 GPU 不支持是真正等待原因
- [x] 定量验证直觉：直觉说"不划算"但算完发现划算——数字会说话，直觉会骗人
- [x] 内存墙催生五大模型架构创新：MoE、GQA、线性注意力/SSM、Flash Attention、量化感知训练
- [x] MoE 架构让模型"大但每次只动一部分"——GPT-4 推测总参数 1.8T 但每次只激活 ~200B
- [x] Claude 的"深度思考"和"执行"都是推理（Inference），不是训练——模型参数在对话中不变
- [x] 审题三问：题目问的是哪个层面？从谁的视角？要求什么深度？

## 形成的判断框架

### 框架 13：供应链风险的三层防御（Supply Chain Risk Defense）

面对关键供应商的依赖风险，按深度递进的三层防御：

| 层级 | 策略 | 手段 | 成本/复杂度 |
|------|------|------|-----------|
| **第一层** | 多源采购（分散） | 引入第二/第三供应商 | 低——但受限于供应商能力差异 |
| **第二层** | 战略锁定（绑定） | 长约、预付款、合资建厂、联合研发 | 中——需要大量资金和长期承诺 |
| **第三层** | 架构替代（减少依赖） | 从产品设计层面降低对该部件的需求量 | 高——但最根本的解决方案 |

**应用场景**：不只适用于芯片供应链。任何"单一关键供应商"风险都可以用这个三层框架分析——先分散、再锁定、最后从架构上减少依赖。

### 框架 14：定量验证直觉（Quantitative Gut-Check）

在做战略判断前，先用简单算术验证直觉。

**经典陷阱**：看到"成本增加 30%"就直觉认为"不划算"，但如果同时"利用率提升 40%"，实际总成本可能反而下降。

**应用场景**：任何涉及"多花一点钱换取效率提升"的决策——技术投资、人员扩编、设备升级——都应该先算一笔总账再做判断。
